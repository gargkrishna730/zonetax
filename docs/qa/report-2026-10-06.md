## Bugs found and fixed

### 1. Cross-AZ traffic counted twice (serious)
Sending 1 GiB between pods in different AZs was reported as **2.16 GB**. A cross-node connection
appears in both nodes' conntrack tables, both agents counted it, and the collector sums agents.
Each agent now counts a connection only if the source pod is on its own node.

### 2. Downloads not counted at all (serious)
A 1 GiB download (server streaming back to a client) was reported as **0.003 GB**: only the
"original" direction of each connection was read, never the reply. Reply bytes are now tracked
and attributed destination to source.

These two errors partly offset each other, which is why an earlier comparison against the AWS
bill landed "within 4%". That claim has been corrected in `docs/accuracy.md`.

### 3. Agent restart produced a huge fake spike (serious)
Restarting one agent reported ~4 GB of cross-AZ traffic in 2 minutes: connections already open at
startup carried their whole lifetime byte count into the first sample. The first sample now only
records baselines. Re-measured after the fix: 2 MB (0.06 GB/h), versus 129.8 GB/h before.

### 4. Traffic through Services was dropped
Traffic to a ClusterIP Service resolved to the virtual Service IP, not a pod, so it was discarded
as unattributable. The destination is now resolved from the connection's reply tuple.

### 5. hostNetwork pods hid node traffic
Pods using the host network share the node's IP, so node traffic was attributed to whichever
daemon was indexed last. Those pods are no longer indexed by IP; node IPs resolve to the node.

### 6. Gap against the AWS bill was invisible
ZoneTax only attributes pod-to-pod traffic, but the bill covers everything. The agent now exposes
`zonetax_agent_unattributed_bytes_total`, the API returns `total_unattributed_gb`, and the
dashboard shows "N GB outside the cluster, not costed".

### 7. "Partial window" was unhelpfully vague
A 40-second collector restart marked a whole 24-hour window "partial", which reads the same as
missing most of the day. The API now returns `unobserved_seconds` and the UI and CLI say
"missed 40s of this 24h window".

### 8. Agent DaemonSet rollout stalled
One node has no free memory for the agent, and `maxUnavailable: 1` meant every other node waited.
Agents now roll 25% at a time, and `agent.priorityClassName` lets the agent schedule on full
nodes (opt-in, since preemption evicts other pods).

### 9. Sticky header overlapped the page
The top bar was sticky but the time bar was not, so on scroll it slid under the top bar and over
the content, with the filter sidebar behind both. Header height is now measured at runtime.

### 10. API dropped a field it had computed
`total_unattributed_gb` was computed by the collector but missing from the response struct, so the
API always returned 0. Found by checking the deployed build, not by a unit test.

## Accuracy after the fixes

1 GiB sent between test pods, measured by ZoneTax:

| Test | Reported | Error |
|---|---|---|
| Upload across AZs | 1.0814 GB | +0.7% |
| Download across AZs | 1.0780 GB | +0.4% |
| Upload through a ClusterIP Service | 1.0816 GB | +0.7% |
| Same-AZ upload (control) | no cross-AZ entry | correct |

The small positive error is packet headers, which AWS also bills.

## Checks that passed first time

- `go test -race ./...`, `go vet`, gofmt; UI lint, types, 82 tests, build.
- Helm lint (both modes) and no drift in the generated raw manifests.
- Helm repo lists every release with images pinned to the tag; both CPU architectures per tag;
  CLI checksums verified and the binary runs; README links resolve.
- Fresh collector cold start: healthy in 3s, first data within two scrapes, honest empty states.
- Upgrade keeps saved history; rollback works.
- API: correct status codes (including rejecting bad ranges), totals equal the sum of entries,
  cost equals GB times price, entries sorted, no negatives.
- Collector restart: history restored, no spike.
- UI in both themes: KPI numbers match the API, every range and view, panels, keyboard, and
  0 axe (WCAG 2.2 AA) violations on the deployed build.
- CLI: every command and range, JSON output, correct exit codes for bad input and an unreachable
  collector.
- Footprint: agents 1-2m CPU and ~18Mi memory, collector 1m and ~25Mi, inside requests.
- RBAC is read-only (get/list/watch on pods and nodes).

## Known limitations (unchanged)

- ZoneTax attributes pod-to-pod traffic only. Traffic to managed services, load balancers, the
  API server and the internet is reported as unattributed, not costed.
- History is in memory, saved to a file; 7-day retention.
- The agent needs host networking and a privileged init container to enable conntrack accounting.
- Workload names are derived from pod names, not looked up from owner references.
